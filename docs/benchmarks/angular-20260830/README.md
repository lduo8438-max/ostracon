## 受控空間量測

`space-controlled.txt` 是完整的命令與輸出。量法的重點在**同一份資料**：

```bash
cp reports/angular-profile-20260827/main.db space-probe.db
# 對副本執行：CREATE INDEX idx_revision_path ON revision(repo_id, lineage_id, path)
ls -l main.db space-probe.db
```

| | |
|---|---:|
| 索引前 | 1,289,707,520 bytes（1,230.0 MiB） |
| 索引後 | 1,477,107,712 bytes（1,408.7 MiB） |
| 增加 | **+178.7 MiB = +14.5%**，每列 64.2 bytes |
| 建立耗時 | 4.6 秒（290 萬列） |

**兩個百分比各自回答不同的問題，都要留著：**

| 問題 | 量法 | 答案 |
|---|---|---:|
| 這條索引本身值多少空間？ | 同一份資料加索引再量 | **+14.5%** |
| 使用者實際會多付多少？ | 從零重建的檔案大小 | **+16.3%**（1,430.4 MiB） |

差額 21.7 MiB 是分兩趟建造的頁面碎片，不是索引的成本。
`README.md` 與 `status.md` 對外用 +16.3%（那是使用者真的會看到的檔案大小），
**但要論證「一條索引值不值得」就得用 +14.5%**——拿兩份分別建出來的檔案相減，
量到的是建造方式而不是索引。
