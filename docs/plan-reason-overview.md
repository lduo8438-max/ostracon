# 1:1 引文能不能當 reason-first overview 的主體：不做

**結論：NO-GO。** 三條門檻裡有兩條在 microsoft/playwright 上不過。
門檻寫在 `reports/probe/oneToOne-criteria.md`，**定稿時間在量測之前**。

量測是只讀的：`reports/probe/one-to-one.mjs`、`subject-quote.mjs`、
`subject-prefix.mjs`（都 gitignored），對 `reports/pip.db` 與 `reports/pw.db`
以 `readOnly` 開啟，沒有動過任何產品資料庫。分組與排序**直接 import 產品那一份**
（`rationaleGroups`、`listEntities`、`orderDeclarations`），沒有另寫一份判準——
所以量到的就是畫面上會看到的東西。

## 待驗的宣稱

pip 那一趟的發現 2：「1:1 引文（一條引文只掛到一個宣告）讀起來正是使用者要的，
能單獨撈出來當 reason-first overview 的主體。」兩套語料並排之後它被裁定為
**種子不是答案**（當時的計數是 pip 152／pw 54）。這一刀是把那句話量到能下結論。

**A 的結果與我的預期相反，而它是這一刀真正的新資訊。** 我原本認為這個畫面
大概只是把 Best explained 第一屏再列一次（那就與「檔案級 hotspots ＝重做
`git log`」同型）。實測不是：playwright 有 **91.8% 的 1:1 宣告根本不在那 400 筆
策展清單裡**，pip 是 69.6%。**可達性缺口在有理由的那一小撮上同樣成立**，而且
一樣隨規模惡化。這一點與這個畫面做不做無關，要留著。

**B 只差 4 條。** 門檻文件已經預先寫明這種情況：「A 極低而 B 只差一點時可以另案
討論，但要重新寫一份門檻，不得在這一份上放寬。」所以這裡不放寬。真正讓它止步的
是 C，那不是差一點。

## C 為什麼不過：主旨被當成理由

playwright 那 30 條裡有 8 條不是理由，而**其中 5 條是整條 commit 主旨**：

    chore(test runner): reuse TestGroup instead of DispatcherEntry (#7924)
    fix(webkit): use protocol to serialize values instead of JSON (#373)
    docs: encourage using `fill` instead of `type` (#24616)

抽取器在主旨行的 `instead of` 上命中，於是「這個做法為什麼被推翻」得到的答案是
一條變更紀錄。把它從抽樣變成全量計數之後，形狀很乾淨：

| | pypa/pip | microsoft/playwright |
|---|---:|---:|
| 1:1 群組 | 197 | 96 |
| 引文**逐字等於** commit 主旨 | 39（19.8%） | 19（19.8%） |
| 其中帶 conventional-commit 前綴 | **0** | **18 / 19** |
| 其中結尾帶 `(#PR)` | 3 | **19 / 19** |
| 全部群組中來自主旨（含片段） | 233 / 814（28.6%） | 132 / 531（24.9%） |

**兩套語料的比例一模一樣（19.8%），可讀性卻完全不同。** pip 的主旨是散文
（`Use logger.indent instead of printing spaces.`）——引它不失真；playwright 用
conventional commit，引它就是引一行 changelog。**這又是「同一個機制、兩種語料
慣例，只在一種上看起來沒問題」**，而主旨型引文本身不是錯的：demo 首頁那條精選
案例（`Dep.ts:hasBit`）刻意就是逐字引主旨，卡片也明說那是主旨而不是抽取出的理由。

**所以這是候選缺陷不是定論。** 要照 103 條與 197 組那兩次的方式人工裁決，
判準得抓詞義（「帶型別前綴與 PR 編號的主旨行不是理由」）而不是長度或位置。
在裁決之前不得加特判。

## 可讀性的判準對結果很敏感，這點要講清楚

上面的「真理由」把 `A instead of B` 這種**只給被否決的替代方案、沒給為什麼**的
引文算進去（產品本來就有 `tradeoff` 這個型別，抽取器 0.4.0 那一刀還特意把
`instead of` 的左半邊一起引進來，所以依產品自己的定義它們是理由）。

**改用嚴格讀法（要求明示「為什麼」）的話，pip 是 21/30 = 70%，也不過。**
兩種讀法下 playwright 都不過，所以結論不因此改變——但這個敏感度足以說明
「1:1 讀起來正是使用者要的」那句話當初是從少數樣本得到的印象。

## 保留與不保留

- **不做這個畫面。** 兩條門檻不過，而 C 不是差一點。
- **保留的發現**：有理由的宣告同樣有可達性缺口（69.6%／91.8% 不在策展清單裡）。
  這不需要新畫面就能處理——搜尋已經涵蓋全索引，缺的是「從理由那一側進去」的入口。
  要不要做是另一個題目，不在這一刀的門檻裡。
- **新的候選缺陷**：帶 conventional-commit 前綴的主旨行被當成理由（playwright
  18/19、pip 0/39）。**要人工裁決才動抽取器。**
- **不得重跑的判準**：這一份的三條門檻。同一個問題要再問，就要新的門檻文件，
  而且必須說明為什麼上一份不適用。
